# UX-05 — In-page terminal session exploration

Issue: [#47](https://github.com/LiiWzz/DeviceBridge/issues/47).
Source baseline: `c3f4c99e508a6466f48bd3efd31c6eb1a1ec64dc`.
**Status: synthetic logic proposal; human flow review pending.**

Open [terminal-logic.html](prototype/terminal-logic.html) directly in a browser
(double-click; no installation/server). This separate, self-contained demo extends
[UX-03](UX-03.md)'s session discovery for the owner's request to type commands in
the web page. The original fleet prototype and its A/B/C variants are unchanged.
The question is about session states, not selection of a new visual layout.

The HTML is a throwaway primary source on branch
`prototype/browser-terminal-states`; retain that branch and issue pointer even
if a reviewed decision is later rewritten into production code. The pure local
model is separate from the DOM shell, but neither is approved production logic.
No validated design decision is promoted yet. Reopen the walkthrough tabs to
reset to known state; free play permits invalid transitions to show their result.

## What to explore

```text
Connect -> preparing -> simulated checks -> attached -> type inert text
  -> Disconnect -> closing -> simulated confirmation -> closed
preparing -> unknown -> reconcile original -> attached / closed
attached -> lost -> discard draft/paste -> reconcile original -> attached / closed
expiry / revocation -> input withheld -> closing -> confirmed closed
denied / host-key failure / unavailable -> no usable terminal
```

The top panel exposes device/account, original session, start count, checks,
input availability, draft/paste, dimensions and buffer use after each action.
Free play includes every failure above. Five guided walkthroughs cover ordinary
closure, uncertain start/duplicate prevention, transport loss with staged paste,
revocation and rejected host key. Select a tab before its ordered steps; using
free play interrupts the walkthrough until a tab resets it.

Enter and the explicit send button produce canned acknowledgements only. Ctrl+C
works while the command field has focus and also has a button. Resize changes a
local label. Arbitrary command text is inert: no SSH, PTY, shell interpreter,
`top`/`vi`, terminal escape parser or actual process signal exists. Output is
plain text via `textContent`, including pasted markup. This is not evidence that
a future terminal renderer safely handles hostile escape sequences.

Pasting into the command field stages a separate preview. Pasting into the
preview or editing it invalidates prior staging. Confirm is explicit, including
for multiline text. Loss clears command draft and paste; reconciliation never
replays them. Do not enter credentials or sensitive text even in this local demo.
The browser DOM can retain text in memory; this is no secure secret-entry UI.

## Provisional observations, not approved decisions

- A pending start needs an original-session reference: a second Connect is
  blocked while preparing, uncertain, lost or closing. Only an explicit simulated
  outcome can reconcile it. A new attempt after rejection/closure starts fresh
  checks; there is no host-key bypass.
- Disconnect is a request, not proof of cleanup. Expiry/revocation withholds
  output/input and retains a closure-pending state. Confirmation is a demo button,
  never an elapsed timeout pretending to be a server acknowledgement.
- Reattachment in this model illustrates one candidate, not an approved contract.
  The simulated result bundles fresh authorization/host-key checks. The real
  design must choose whether reattachment is supported at all and prove its
  authority, identity, audit and revocation semantics independently.
- Background processes can outlive SSH; closure cannot undo executed commands.
  Reset erases local demo state only. Real cleanup needs server-owned bounds.

Human review should inspect all walkthroughs, blocked transitions, expiry and
service denial, safe paste/edit/cancel, keyboard-only operation, narrow screens,
zoom and screen-reader announcements. Record browser/OS/viewport and exact
observations. The local diagnostic trace is not human validation or accessibility
acceptance. No real-browser rendering, focus, paste events or keyboard execution
has been verified: BrowserOS neo MCP is unavailable in this session. No browser
automation fallback was substituted.

## Dependencies, evidence and rollback

[ADR-003](../adr/ADR-003-browser-terminal-scope.md) permits synthetic BTERM-UX
before production gates. This proposal grants no SSH authority, picks no gateway,
credential, terminal library, endpoint or protocol, and changes no ADR status.
ADR-001/002/003 approval, M01/M02 acceptance, full WEB-01 and architecture/security
decisions still precede real integration. The UX-03 native CLI baseline remains;
this is a proposed extension, not an approved replacement.

Exact syntax, document/scope checks and exploratory model traces are in
[validation.txt](../evidence/terminal-ux/validation.txt), with reproducible
[inspect.mjs](../evidence/terminal-ux/inspect.mjs). It compiles the inline scripts
and exercises the pure model only, not DOM/browser behavior. No prototype test
suite is introduced. [secrets.txt](../evidence/terminal-ux/secrets.txt) captures
the scanner commands/output; pattern scans cannot certify absence of all secrets.

No network, persistent storage, external assets/dependencies, device allocations,
flash writes, root use, production configuration or command execution is added.
The demo bounds command/paste to 1,024 characters each and output to 40 entries
of up to 1,200 characters; resize ranges 20–240 columns / 5–80 rows. These are
local demonstration limits, not approved production budgets. Browser memory and
actual supported-device PTY costs remain unmeasured; 128 MB RAM / <=16 MB idle
RSS targets and ARMv7/AArch64/Windows validation remain unresolved. No application
build, real SSH, security/crypto, hardware or hosted CI pass is claimed here.

Rollback by a reviewed revert PR into `develop`, removing this standalone demo
and its links while preserving primary-source/decision provenance. No deployed
session, device action, stored data or credential needs recovery. Human manual
approval/merge only; documentation merge does not approve security or UX gates.
