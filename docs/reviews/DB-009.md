## Architecture, threat model and resource assessment

- The control service binds validated loopback IP literals and unprivileged
  ports; only health/readiness routes exist. Timeouts and request headers are
  bounded. It has no aggregate connection cap and no authenticated application
  API. Local users remain inside its documented trust boundary; never treat a
  reverse proxy as production authorization.
- Agent JSON reads are bounded to 4096 bytes, reject invalid/duplicate/unknown
  inputs and nonregular files, and sanitize parse diagnostics. Its idle loop
  sleeps without per-iteration allocation, network or flash writes; startup
  allocates parser/config/signal state. A blocked log sink can delay shutdown.
  Source inspection does not establish peak/idle RSS or CPU on embedded Linux.
- Relay accepts disabled transport only and CLI connect fails closed. Reserved
  maxima multiply to 1024 × 1048576 = 1 GiB if future transport naively allocates
  every buffer. No such allocation exists now. M02 must approve/enforce aggregate
  budgets, authorization/expiry and bounded reconnect behavior before enabling it.
- Compose is development-only: loopback publication, nonroot postgres, dropped
  capabilities and resource limits; TCP authentication is checked. Docker access,
  trusted local sockets and the development administrative DB role remain strong
  host trust assumptions. Migrations use a transaction/advisory lock and drift
  checks; smoke tests cover rollback, failure atomicity and concurrent execution.
- Packages assume a trusted publisher, operator-owned prefixes and trusted
  parents. SHA-256 detects corruption, not publisher identity; checks are not a
  defense against the same UID changing files concurrently. GNU Rust ARM outputs
  need the matching loader/libc/ISA and are not universal Buildroot/Yocto binaries.
- CI tokens are read-only, checkout credentials are not persisted, and there is
  no deployment, secret injection, self-approval or automatic merge. Mutable
  action/image tags and compiler/dependency provenance remain supply-chain risks.
  Gitleaks patterns do not certify absence of all secrets. No current vulnerability
  database audit, penetration test or reproducible-binary certification is claimed.
